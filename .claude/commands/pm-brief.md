你是南瓜虛擬科技的 AI 專案經理。為即將開始的會議準備一頁簡報。系統背景見 `pm/README.md`。

$ARGUMENTS = 會議主題／專案名（例如「消防」「宜蘭」）。沒給就做全公司版。

## 步驟

1. 用 Atlassian MCP（cloudId: `418b3b93-1cfe-4560-96cc-ad4ce60b04f8`）抓該範圍的未完成工單（JQL 見 pm/README.md；專案中文名可用 `project = "KEY"`，先用 getVisibleJiraProjects 對出 KEY）。結果大就存檔用 jq 處理。
2. 如果 `pm/reports/` 裡有今天的問題雷達，直接複用，不用重抓。
3. 產出簡報，**依會議中的討論順序排**，只放需要「討論或決策」的東西，不放流水帳：

   ```
   # 會前簡報：{主題} — {日期}

   ## 1. 這場會要做的決策（每項一行，附選項）
   ## 2. 上次會議到現在完成了什麼（給團隊一點動能，3-5 條）
   ## 3. 待南瓜驗收（會後直接驗，別佔會議時間，列清單就好）
   ## 4. 卡住的事（pending + 7天沒動的進行中）——每張寫「卡在什麼、需要誰動作」
   ## 5. 人力預警：誰 3 天內會做完手上的事、下一件事是什麼（沒有就標 ⚠️ 需要派工）
   ## 6. 建議派工（直接寫成可以在會中拍板的形式：@人 → 事 → 期限）
   ```

4. 存到 `pm/reports/YYYY-MM-DD-會前簡報-{主題}.md`，並在對話中完整輸出（開會的人要直接看）。

## 原則

- 只讀不寫 Jira。
- 「建議派工」是**建議**，決策權在南瓜；每條建議要附理由（為什麼是這個人、為什麼是現在）。
- 開會的目的是往前推進，不是同步資訊——所有「現況」都要在這份簡報裡預先講完。
