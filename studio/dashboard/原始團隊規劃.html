信箱協議 · Mailbox Protocol

多 terminal 協作的基礎建設。所有 agent 透過檔案郵箱溝通。

📬
核心理念
Agents 不直接互通，透過信箱協作。沒有對話記憶、沒有 IPC — 只有資料夾、檔案、和紀律。

📬 南瓜虛擬科技 · 檔案郵箱協議（Mailbox Protocol）

> 多終端機 agent 之間怎麼溝通？答案是檔案系統當共享記憶體。
> 沒有對話記憶、沒有 IPC、沒有訊息佇列 — 只有資料夾、檔案、和紀律。

🎯 核心理念

Agents 不直接互通，透過郵箱協作。 
T6 Gameplay Programmer 寫好 weapon code
  ↓
寫一份 PR notice 到 studio/mailbox/outbox/T2/
  ↓
T2 CTO 開新 session 時讀 inbox（= 別人的 outbox/T2/）
  ↓
CTO 看完後寫審查結果到 studio/mailbox/outbox/T6/
  ↓
T6 下次開機時看到 inbox 有東西
好處：
  • ✅ 不依賴 agent 同時在線
  • ✅ 不會因為 context 太長被截斷
  • ✅ 所有溝通有檔案紀錄，事後可追蹤
  • ✅ 可以離線審閱 / 回 PR

📁 資料夾結構

studio/mailbox/
├ inbox/                  # 每個 terminal 看自己的 inbox
│  ├ T1/                  # CEO 收件匣
│  ├ T2/                  # CTO 收件匣
│  ├ T3/                  # CAO 收件匣
│  ├ T4/                  # CMO 收件匣
│  ├ T5/                  # Lead Programmer 收件匣
│  ├ T6/                  # Gameplay Programmer 收件匣
│  ├ T7/                  # QA 收件匣
│  ├ T8/                  # Tools Programmer 收件匣
│  └ T9/                  # Scarlet 收件匣
├ outbox/                 # 寄出的訊息（給別人讀）
│  ├ T1/                  # 給 CEO 的訊息丟這
│  ├ T2/                  # 給 CTO 的訊息丟這
│  └ ...（同上）
├ blocked/                # 被卡住、等待外部資源
│  └ <task-id>.md
└ archive/                # 已處理過的訊息
   └ YYYY-MM/

重要對應規則

> 「給 X 看的訊息」放在 outbox/X/，X 自己讀就是 inbox/X/。

實作上，這兩個是同一個資料夾，只是兩個視角：

# 方案 A：symbolic link
ln -s studio/mailbox/outbox/T1 studio/mailbox/inbox/T1

或者單純規定：

寄信：寫到 studio/mailbox/outbox/<目的地>/
收信：讀 studio/mailbox/outbox/<自己>/
我推薦後者（單一資料夾不複製），路徑更清楚。
