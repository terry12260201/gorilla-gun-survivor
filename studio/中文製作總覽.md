# Gorilla Gun Survivor 中文製作總覽

更新時間：2026-05-18

## 一句話結論

目前遊戲是「可跑、可測、已具備核心雛形」的 prototype，但還不是完整好玩的商品版本。

現在距離「完整、好玩、可以放心展示」大約還有 **35% 到 40%** 的路要走。  
距離「可以賣 $15 的完整版本」大約還有 **60% 到 70%** 的路要走。

## 目前缺口

| 類別 | 缺口 | 影響 |
| --- | --- | --- |
| 新鮮感 | 新武器、新技能、新角色不足 | 玩幾輪後重複感會出現 |
| 地圖變化 | 目前 arena 變化少 | 3D survivor 的空間優勢還沒完全發揮 |
| 敵人節奏 | 敵人組合與壓力曲線還需 QA | 可能某些時段太空或太暴力 |
| 數值調校 | HP、傷害、XP、掉落率還沒系統化測 | 好玩度不穩 |
| 視覺美術 | placeholder 與資產一致性不足 | 商品感不足 |
| 效能 | 還沒有完整 5/10/15 分鐘 baseline | 後期怪多時風險未知 |
| 測試流程 | 需要固定測試表與回報節奏 | 目前主要靠人工印象 |

## 接下來開發順序

### 階段 A：資料穩定與可測化，目前進行中

目標：讓遊戲可以安全加內容，不會每次改數值都改壞程式。

已完成：

- 武器資料搬到 JSON。
- 武器資料驗證器。
- Build gate 自動檢查武器資料。
- 中文 dashboard 與測試節點。

下一步：

- 建立 QA 測試回報表。
- 新增第一把 data-driven 新武器。

### 階段 B：新內容第一輪

目標：讓玩家明顯感覺「有新東西」。

預計內容：

- 新武器 1 把。
- 新敵人 1 種。
- 新技能或主動能力 1 個。
- 基礎數值調整。

你可以測試的時間點：

- 新武器能在升級卡出現，且選了會開火。
- 新敵人能出現，且有明顯行為差異。
- 新技能有按鍵或觸發方式。

### 階段 C：好玩度迭代

目標：不是加更多，而是讓 3 到 5 分鐘內有節奏。

要調的東西：

- 敵人生成速度。
- XP 掉落與升級速度。
- 血量壓力。
- heart 掉落與救場頻率。
- 武器卡出現率。
- miniboss 時間與威脅感。

你要測：

- 前 1 分鐘會不會太無聊。
- 第 2 到 4 分鐘是否有壓力。
- 是否常常不知道自己怎麼死。
- 升級選項是否讓你期待。

### 階段 D：內容擴張

目標：做出「可以反覆玩」的雛形。

預計內容：

- 新地圖或 arena variant。
- 新角色 1 位。
- 新技能組。
- 新武器 3 到 5 把。
- 敵人組合與 wave event。

### 階段 E：商品化與效能

目標：接近可展示、可發佈。

需要：

- 5/10/15 分鐘效能測試。
- UI 中文與英文整理。
- 音效與 BGM 完整化。
- 結算畫面與 meta progression 打磨。
- GitHub Pages / build deploy 穩定。

## 你何時要測試

| 測試點 | 狀態 | 你要測什麼 |
| --- | --- | --- |
| Checkpoint A：資料基礎穩定 | 現在可測 | 開遊戲、升級、看武器卡、選武器、確認 auto weapon 開火 |
| Checkpoint B：第一把新武器 | 尚未完成 | 新武器是否出現、是否開火、是否和舊武器有差異 |
| Checkpoint C：第一輪好玩度 | 尚未完成 | 3 到 5 分鐘是否有節奏、有壓力、有期待 |
| Checkpoint D：新怪或新技能 | 尚未完成 | 行為是否明顯、是否增加變化 |
| Checkpoint E：新地圖 | 尚未完成 | 空間是否更有趣、是否看得懂、是否卡住 |

## 怎麼迭代才會越來越好玩

每次迭代只做一個主題，不亂加：

1. 加一個新內容。
2. Build 與 runtime 驗證。
3. 產生測試清單。
4. 你玩 3 到 5 分鐘。
5. 回報三件事：
   - 最好玩的瞬間。
   - 最煩或最不懂的地方。
   - 想不想再玩一局。
6. 根據回報調數值或刪改內容。

判斷好玩度的標準：

- 第 30 秒：玩家知道要做什麼。
- 第 2 分鐘：玩家感覺壓力開始上來。
- 第 4 分鐘：玩家已經有 build 方向。
- 第 7 分鐘：玩家想撐到下一個升級或 boss。
- 死亡後：玩家想再玩一局，而不是關掉。

## 美術與 3D 管線判斷

可以做，但不是一步到位。

| 能力 | 現在狀態 | 解法 |
| --- | --- | --- |
| 概念設計 | 可以 | Concept Artist 產 prompt / 參考規格，CAO 審核 |
| AI 圖像 | 可以 | 需要使用 image generation，產到 `art/concepts/` |
| 3D 規格 | 可以 | 3D Specialist 寫 model brief、poly budget、材質、LOD |
| Blender 自動建模 | 部分可以 | 沒有 MCP 時用 Blender Python 腳本；有 MCP 後可互動控制 |
| 動畫 | 可以規劃，實作需資產 | Animation Director 先定狀態機與動作清單 |
| 特效 | 可以 | 先用 Three.js VFX，之後由 VFX Artist + Volt 控粒子預算 |
| 匯入遊戲 | 可以 | `.glb` 放到 `public/assets/custom/`，JSON 或 code 引用 |

第一個美術管線任務：
