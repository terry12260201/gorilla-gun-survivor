03兩個 Terminal 怎麼跑

Terry 原始需求是多開 terminal 並保留紀錄。真正的設計不是保存視窗捲軸，而是用 scripts 把過程寫進 .ops/logs。

Terminal A：Live Ops / Dev Server

負責啟動、查詢、停止遊戲 dev server。

cd "E:\Project\2026\Gorilla Gun Survivor — Web Edition"
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\automation\scripts\start-dev.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\automation\scripts\status-dev.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\automation\scripts\stop-dev.ps1
Terminal B：Build / Dashboard

負責驗證、build、更新 Terry 進度頁。

cd "E:\Project\2026\Gorilla Gun Survivor — Web Edition"
npm run validate:weapons
npm run build
npm run dashboard:update
可信紀錄：.ops/logs、.ops/pids、Obsidian 筆記與 Dashboard，不是 terminal scrollback。

  • 長篇企劃與設計討論。
  • AI 團隊角色扮演、任務信件、評審文字。
  • 整理 pending changes、inbox/outbox。
  • 把需要 Terry 決策的問題寫清楚。

規則很簡單：同一個 process 只給一個 agent 管；同一份檔案不要兩邊同時改；重要結論一定落地成文件。

06GPT Image 2 → Blender → Game

官方模型名稱是 gpt-image-2，不是 GPT Image 2.0。這條管線目前已能示範，但 Blender 產物仍需要人工美術修正。

1 Brief寫用途、玩法、輪廓、材質、禁忌。
2 GPT Image 2產 reference sheet。
3 CAO Review確認可讀性與方向。
4 BlenderPython fallback 或 MCP 建模。
5 GLB輸出到 game assets。
6 QA在遊戲內測載入與辨識。
$env:OPENAI_API_KEY="你的 key"
npm run art:concept -- studio/art-pipeline/briefs/plasma-bomber-v1.json
GPT Image 2 產出的 Plasma Bomber reference sheet。後續 Blender Python 產物和這張圖仍有差距，這是目前管線需要改善的地方。

08怎麼看遊戲內 QA

正常遊戲裡 bomber v1 45 秒後解鎖，v2 90 秒後解鎖。為了不要讓測試卡在等待與死亡問題，已加 URL-only QA mode。

npm run dev -- --host 127.0.0.1 --port 5174

打開：

http://127.0.0.1:5174/?qaBombers=1
  • QA mode 會快速生成 bomber 與 plasma_bomber_v2。
  • 正常遊戲不帶參數，不受影響。
  • QA 報告骨架：qa/reports/run-bomber-readability-20260519.md

10對外可以怎麼講

我不是單純叫 AI 寫遊戲，而是在搭一個能運作的 AI 製作中控。Codex 負責可驗證的工程動作，Claude 負責長篇企劃與團隊角色，Obsidian 負責長期記憶，Dashboard 負責讓人看懂進度，`.ops/logs` 負責 terminal 的可信紀錄。GPT Image 2 負責概念圖，Blender Python 先把模型管線打通，OpenSpec 則把聊天中的設計轉成可以版本化的規格。
